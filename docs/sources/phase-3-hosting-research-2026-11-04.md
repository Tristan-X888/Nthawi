Evidence register for the
[Phase 3 design bundle](../infrastructure/phase-3/README.md). It records dated
observations and official documentation statements. It selects nothing: the
design documents make the decisions and cite these IDs. Nothing here authorizes
a provider operation, purchase, DNS change or deployment.

## Findings that drive the design

- Nothing exists to reuse at Netlify, Render or Resend. Every hosting resource is
  future work for Phase 5 or later.
- Ordinary Netlify rewrites (26 seconds) and functions (6 MB buffered) cannot
  carry 10 MiB originals or long streams; those need direct API routes.
- `x-nf-sign` proves only Netlify provenance, deployment context, site and
  expiry. It binds no method, path or body and is not user authorization.
- Render cannot change a service's region; Frankfurt is its only EU region. The
  existing Neon project is in London, so the API-to-database hop crosses
  providers and countries.
- Netlify's Next.js support for 16.4.1 is a provider claim, not a verified
  adapter result (NXT-01, NET-05). Phase 5 must prove the required features.
- None of the Render pages read documents egress denial, a customer-selected
  OCI runtime or per-job sandbox enforcement. That absence drives the parser
  decision in the [data and isolation evidence](phase-3-data-isolation-research-2026-11-04.md).
