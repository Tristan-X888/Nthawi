## Findings that drive the design

- Seven days of native history needs Neon Launch or Scale (NEON-01). Native
  history alone is neither independent of the provider nor an object backup.
- A complete logical export of forced-RLS tables needs a session that can
  bypass row security (PG-01, OBS-D06). The documented route is a
  Console/API-created role that is a member of `neon_superuser` and switches to
  it with `SET ROLE` (`pg_dump --role`, NEON-04). Role attributes are not
  inherited through membership, so Phase 4 must prove the exact path.
- R2 lifecycle expiry is asynchronous (R2-02); application deletion must revoke
  access immediately and verify purge itself.
- A standard long-lived R2 Object Read & Write parent key is not create-only
  (R2-05). Keep it in the independent recovery plane. The selected intake
  narrows application operations; bucket locks protect retained copies. R2
  action-scoped temporary credentials exist, so do not generalize the parent
  permission limitation into a claim that no narrower delegation is possible.
- A presigned URL is a bearer capability until it expires. Immediate revocation
  needs an authenticated download gateway.
- ClamAV needs at least 3 GiB of memory (CAV-01) and must not expose `clamd`'s
  unauthenticated TCP socket beyond the scanner container.
- gVisor documents host-side network removal, filesystem mediation, bounded
  overlays and cgroup enforcement (GV-01 to GV-04). Guest process limits need
  explicit adversarial proof because guest processes are not host processes.
